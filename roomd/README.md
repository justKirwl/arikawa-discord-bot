# roomd

Realtime playback-room service for the cinema bot (PLAN.md, Rust scope).

`roomd` owns room state, synchronization and WebSocket fan-out. It is
deliberately unaware of Discord: the Go bot passes opaque `guild_id`,
`channel_id`, `user_id` and `media_id` values, and the browser talks to
`roomd` directly over WebSocket. Video bytes never pass through this service.

## Layout

```
proto/roomd/v1/room.proto    RoomService contract (Go <-> Rust)
proto/media/v1/media.proto   MediaRef + MediaService contract (Go <-> Rust)
docs/protocol.md             browser <-> roomd WebSocket protocol v0.1
src/config.rs                ROOMD_* environment configuration
src/telemetry.rs             tracing (pretty or JSON)
src/http.rs                  HTTP listener: /healthz, /readyz
src/grpc.rs                  gRPC listener and RoomService handlers
src/state.rs                 in-memory room registry
src/pb.rs                    generated prost/tonic bindings
src/shutdown.rs              Ctrl+C / SIGTERM handling
tests/rooms_grpc.rs          gRPC integration test for the room lifecycle
```

Protobuf bindings are generated by `build.rs` with a vendored `protoc`, so no
system protobuf installation is required.

## Run

All commands below are run from this directory.

```sh
cp .env.example .env
cargo run
```

| Variable | Default | Meaning |
| --- | --- | --- |
| `ROOMD_GRPC_ADDR` | `0.0.0.0:50051` | gRPC listener for the Go bot |
| `ROOMD_HTTP_ADDR` | `0.0.0.0:8080` | HTTP listener (health, later `/ws`) |
| `ROOMD_LOG_FORMAT` | `pretty` | `pretty` or `json` |
| `ROOMD_LOG_FILTER` | `info` | fallback for `RUST_LOG` |

Endpoints:

- `GET /healthz` — liveness, always `200` while the process runs;
- `GET /readyz` — `200` once both listeners are bound, `503` before that.

## Contracts

`proto/` and `docs/protocol.md` are shared with the Go developer and the web
client, and require review from both sides. Changes to them go in a dedicated
`contract-change` commit, never mixed with feature work. When the monorepo
from PLAN.md §1 exists, these files move to its root `proto/` directory
unchanged.
