# roomd

Realtime playback-room service for the cinema bot (PLAN.md, Rust scope).

`roomd` owns room state, synchronization and WebSocket fan-out. It is
deliberately unaware of Discord: the Go bot passes opaque `guild_id`,
`channel_id`, `user_id` and `media_id` values, and the browser talks to
`roomd` directly over WebSocket. Video bytes never pass through this service.

Protobuf bindings are generated by `build.rs` with a vendored `protoc`, so no
system protobuf installation is required.

## Run

All commands below are run from this directory.

```sh
cp .env.example .env
cargo run
```

| Variable | Default | Meaning |
| --- | --- | --- |
| `ROOMD_GRPC_ADDR` | `0.0.0.0:50051` | gRPC listener for the Go bot |
| `ROOMD_HTTP_ADDR` | `0.0.0.0:8080` | HTTP listener (health and `/ws`) |
| `ROOMD_LOG_FORMAT` | `pretty` | `pretty` or `json` |
| `ROOMD_LOG_FILTER` | `info` | fallback for `RUST_LOG` |
| `ROOMD_JWT_PUBLIC_KEY` | — | base64url Ed25519 public key (JWK `x`); `/ws` answers `503` while unset |
| `ROOMD_JWT_ISSUER` | `cinema-bot` | required `iss` claim; an empty value disables the check |
| `ROOMD_JWT_KEY_ID` | — | required JWT header `kid`; unset accepts any key id |
| `ROOMD_ROOM_IDLE_TIMEOUT` | `300` | empty-room lifetime in seconds before it is closed (S3.7) |

Endpoints:

- `GET /healthz` — liveness, always `200` while the process runs;
- `GET /readyz` — `200` once both listeners are bound, `503` before that;
- `GET /ws` — WebSocket upgrade; send `join` with a room token first.

## Dev WebSocket session

`examples/dev_token.rs` uses a public development key pair (the matching public
key is already in `.env.example`). Never use it outside local development.

```sh
# Create a room through the real gRPC API and mint a host token for it.
cargo run --quiet --example dev_create_room
cargo run --quiet --example dev_token -- --room <room_id> --role host
```

Then connect any WebSocket client to `ws://127.0.0.1:8080/ws` and send:

```json
{ "type": "join", "token": "<token>" }
```

The first text frame is `state` (empty `media_ref` until `SetMedia` is called).
Invalid signatures and expired tokens answer with `invalid_token` /
`token_expired` and close with `1008`, per `docs/protocol.md` §3.1 and §12.

## Docker

From the repository root, `docker compose up --build` starts `roomd` together
with the Go bot. This directory also has a roomd-only compose file:

```sh
docker compose up --build
```

## Contracts

`proto/` and `docs/protocol.md` are shared with the Go developer and the web
client, and require review from both sides. Changes to them go in a dedicated
`contract-change` commit, never mixed with feature work. When the monorepo
from PLAN.md §1 exists, these files move to its root `proto/` directory
unchanged.
